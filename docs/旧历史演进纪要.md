## 2. 八份设计文档要点

旧历史 `docs/` 下有 8 份文档（新历史中已随干净提交重新提交，内容基本保留）。要点如下：

### 2.1 产品方向
- **定位**：`rysh` = 你的 shell + AI 副驾（copilot），一键切换，同一屏、同一输入行。不替代终端、不替代 shell。
- **差异化**：shell 优先（不是 agent 优先）；所有配置热生效（改完即生效、无需重启）；会话跟随 `cd` 换目录而不丢失。
- **对标/区分**：codex / claude code / pi / grok 的 GUI/CLI 都做不到"不离开 shell 就问答 + 换目录不换会话"。

### 2.2 需求分析
- 核心场景：工作中途不离开 shell 问 AI；给 AI 多步任务并旁观；单终端多 AI 会话（`/new` `/ls` `/resume`）。
- 硬约束：shell 模式零侵入（不改 PS1、不影响 vim/less 等全屏程序）；跨平台（Linux/macOS/Windows）。

### 2.3 架构设计
- **进程模型**：单进程单 PTY；AI 会话是"磁盘流"（`~/.rysh/sessions/<id>/messages.log`，append-only JSONL），不是进程也不是 PTY；切会话 = 杀旧登录 shell 整棵进程树 + 同一 PTY 重启登录 shell + 分隔行 + 尾部回放（不清屏）。
- **核心模块**：PTY 层（`aymanbagabas/go-pty`，Unix=creack/pty、Windows=ConPTY）/ 输入路由与模式状态机 / 执行通道（bash 围栏 → 独立执行器，截断 + 超时杀进程组）/ Agent Loop / Provider 抽象（OpenAI 兼容 SSE）/ 会话与上下文（**cwd-as-data**：会话不绑目录，cwd 是事件字段）/ 配置（`~/.rysh/config.toml` 热读）/ TUI（一屏一流 v4）。
- **Agent 预算管理（§3.9）**：不设轮数硬上限；停止条件收敛为 `^C` / LoopGuard 判疯 / 预算触顶；Token 记账（CJK×1.0 + 其余÷4，+10% 余量，usage 校准）；L1 工具输出瘦身（滑窗 64KB 保留区外替换为占位）+ L2 LLM 摘要压缩（**状态交接**，触发线 85%/回落 50%）；LoopGuard 分级（签名=命令+exit code+输出前 N KB；Warn≥2 / Block≥4 / Break≥6 或窗口饱和后同签名占比>60%）；FinalRound 强制收尾统一出口。
- **多会话（§3.10）**：`created`/`updated` 台账 + `ctl/<pid>.cmd` 控制通道（子进程写一行 `switch <id>`，主循环 250ms 轮询）+ `/ls` 六列渲染（编号/ID/名字/创建/更新/占用）+ 会话互斥（一个会话只被一个实例附加）。
- **ADR 摘要**（9 条，详见 §3）。
- **非目标**：多任务/多窗口（交给 tmux）/ 模型自进化 / 与 wukong 合并底座。

### 2.4 工作计划
- 里程碑 M1→M7 逐项任务清单 + 验收口径 + 进度记录（含 2026-08-24/26/27 的进度快照）。
- M1 验收：三平台 `rysh` 内可用 vim/git 等交互程序；M2 验收：误入 AI 模式后 Ctrl+Tab 回车即执行，零重打；M3 验收：多轮追问 + `/model` 热切换。

### 2.5 技术选型调研
- 对比 Go / Rust / Zig（终端 PTY 生态、并发生态、静态分发）。
- **定 Go**：静态单文件分发（`CGO_ENABLED=0`）/ PTY 与终端库生态成熟（creack/pty、go-pty、bubbletea）/ 并发生态成熟（goroutine 天然适合 PTY 读写 + 会话日志 + agent loop 并发）/ 团队更熟、迭代快。
- PTY 跨平台统一走 `aymanbagabas/go-pty`（Windows=ConPTY）。

### 2.6 agent 执行流程设计（M7）
- **根因 R1-R9**：围栏块协议 / 4 轮上限 / 只有 bash 一种工具 / 30s 硬超时 / 无权限模型 / 无任务规划 / 无 token 概念 / 无重试 / 系统提示只有一句话。
- **参考 5 个 harness**：crush（Go）/ codex（Rust）/ opencode（TS）/ deepseek-harness（TS）/ grok-build（Rust）。收敛出的共同骨架：原生 function calling 驱动 → 工具执行 → 结果回喂 → 循环，外加六道配套（审批 / 长命令 / 上下文压缩 / 循环保护 / 重试 / 会话持久化）。
- **rysh 取舍**：薄层产品（不做多任务/云/沙箱/MCP/Rhai workflow），六道配套骨架全部采纳；**唯一差异化保留**：围栏块协议作为弱模型（本地 llama-server）的兜底（五个参考项目都没有，是 rysh "BYO 本地模型"定位的刚需）。
- **工具集**：bash / read / write / edit / glob / grep / ls / todo / job_output / job_kill。
- **审批**：ask/auto 审批 + 只读自动放行 + 允许规则（yolo 档）。
- **子任务**：管理者模型（^C 三级：审批→拒答 / 命令→只中断命令 / 子任务→先停子任务管理者续跑）；深度 1（不嵌套）。

### 2.7 上下文管理对比分析
- **病症**：9 小时任务陷入「上下文变重 → 压缩 → 忘了要干嘛 → 读文件重新定位 → 又变重」循环。
- **对比 5 个 harness**：pi / codex / opencode / grok-build / deepseek-harness。
- **pi 特色**：文件即上下文（上下文里只有指针，知识默认在磁盘）/ 会话是树 / 压缩是自包含 checkpoint（`[compaction] + 其后所有 entry`，更早的永不读）/ 结构化 checkpoint 摘要（`## Goal / Constraints & Preferences / Progress / Key Decisions / Next Steps` 固定格式）。
- **关键洞察**：压缩不是"把历史弄短"，而是**状态交接（handoff）**——把"目标、进度、决策、已知文件、当前存活状态"无损移交给一个没参与过对话的新模型。凡是把压缩当"截断+摘要"的都会掉进"忘了要干嘛"；只治理源头不管交接的，循环只是变长不会消失。

### 2.8 主屏方案（完整版方案 B）
- **动机**：备用屏（alt screen）没有滚动历史，AI/shell 输出都滚不动。
- **核心改动**：启动不进备用屏、直接跑主屏；退出不清屏（终端原生滚动）；删状态栏与 DECSTBM 滚动区；AI 提示符承载身份信息（`cwd / model / [AI]:`）；spinner 放末行；会话切换回放统一时间线（尾部 N 行、按块原子截断）；shell 模式零侵入（不改 PS1）。
- **提示符标记（2026-08-31 修订）**：`[tui] prompt_marker` 缺省 `auto`；① 标题层（所有 shell）：rysh 接管终端标题，过滤子 shell 的 OSC 0/2；② bash 层：`PROMPT_COMMAND` 注入暗色 `(rysh) ` 前缀（用户 rc 若自己赋值则用户胜出、标记静默退场）；③ zsh 层：`ZDOTDIR` 临时目录（只含单个 `.zshenv`，注册 precmd 钩子后指回真实 dotdir）；④ fish 等：只做标题层，提示符前缀走 `RYSH_INSIDE` opt-in。
- **取舍**：换来 shell 与 AI 输出都进终端原生 scrollback（`Shift+PgUp` 可回看）；代价是长回复把 `[AI]:` 滚进历史时没有常驻模式指示。

## 3. 九条 ADR（架构设计 §5 摘要）

1. **shell 与 AI 共用一条输入行**：Shift+Tab（或行首空格）切换；进入 AI 时 shell 未提交命令带进 AI 草稿（行编辑器 shell `^A+^K`、纯 shell `^U`）；退出时草稿回注 shell（不带回车）；`!` 开头视为误输入到 AI 的 shell 命令（不执行、不发给模型、提示两条出路）。
2. **cwd-as-data**：会话不绑目录，cwd 是事件字段，天然支持目录切换与上下文出处。
3. **Go 而非 Rust/Zig**：静态单文件分发 + 终端/PTY/并发生态成熟 + 团队更熟。
4. **不做多任务**：交给 tmux，聚焦交互体验。
5. **不绑定本地模型**：provider 抽象，本地/云端自由；不做自进化。
6. **三平台支持，Windows 默认 PowerShell**：`shell = "auto"` 可覆盖；PTY 统一 `aymanbagabas/go-pty`。
7. **一屏一流**（v4 → 主屏方案）：AI 与 shell 共享同一屏幕、同一终端流；不切 alt screen、不清屏、不动滚动区、不改光标、不回放/重建 shell 画面；AI 模式下 shell 输出缓冲 + 记录日志，返回时一次性刷新。
8. **无轮数上限的 agent 循环**：移除 `maxToolRounds`；靠 LoopGuard 防发疯、靠 token 预算驱动自动压缩续命；一切非常规终止汇入 FinalRound。
9. **AI 模式 = 管理者模型**（M7.7）：传统 shell 本体永远是管理者和监控者；AI 模式核心是上下文管理，管理者像守财奴一样吝啬上下文；重活一律委派子智能体（同进程、独立上下文、复用全套守卫）；过程不进管理者上下文、只有紧凑状态与有界报告过缝；^C 三级语义。
