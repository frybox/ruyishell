# 主屏方案（完整版方案 B）设计文档

> 状态：已批准（2026-08-29 起进入实现）
> 关联：v4 一屏一流（2026-08-26）、备用屏接管终端（2026-08-27，本方案 revert 之）
> 一句话目标：ryshell 启动不再进入备用屏，直接跑在主屏；用终端原生滚动替代应用级滚动，去掉状态栏，会话切换回放统一时间线（含 shell 对话）并以尾部 N 行、按块原子截断。

---

## 0. 目标

1. **彻底解决"无法滚动"**：根因是备用屏（alt screen）没有滚动历史。退回主屏后，shell 与 AI 模式的输出都落入终端原生 scrollback，用户可用 `Shift+PgUp` / 鼠标滚轮自由回看。
2. **零应用级滚动代码**：不再需要 app-level 视口、鼠标追踪、PgUp/PgDn 处理（这些是之前方案 A 的代价）。
3. **去掉状态栏与 DECSTBM 滚动区**：退出时屏幕内容保留（像普通命令一样），由终端模拟器负责滚动。
4. **AI 模式提示符承载身份信息**，`spinner` 放末行；**shell 模式零侵入**，不改 PS1，靠启动横幅标识。
5. **会话切换回放统一时间线**（自然语言对话 + shell 对话交织），尾部 N 行、按块原子截断，两个模式都可回放。

---

## 1. 背景与动机

- 备用屏是 xterm 私用模式 `\x1b[?1049h/l`（非 ANSI 标准），**没有滚动历史**，只是一块固定大小的可见画布。
- ryshell 自 2026-08-27 起"启动即进入备用屏"，动机是"像 vi 一样独占终端、退出还原用户原屏 + 崩溃清理"（`工作计划.md`）。
- 代价：备用屏无 scrollback → AI / shell 输出都滚不动。`aiui.go:245` 把 `PageUp/PageDown/CtrlEnd` 当 no-op，且从不开启鼠标追踪，于是当前构建里**任何位置都无法滚动**。
- 本方案 revert 备用屏接管，回到 2026-08-26 v4「跑在主屏」的状态（当时尚未加启动备用屏）。v4 的「一屏一流、AI↔shell 不切屏、不重建」核心不变，只是不再用备用屏做"终端接管"。

## 3. 详细设计

### 3.1 启动 / 退出 / 崩溃清理

- **启动**：删除 `main.go:635` 与 `:1259` 的 `EnterAltScreen()`。改为打印两行暗色启动横幅：
  `rysh · hy3/hy3 · session <id>` + 一行切换键提示
  `<mode_switch 键>（或行首空格）进入 AI 模式 · exit 退出 rysh`（键名随 `[keys] mode_switch` 配置，缺省 Shift+Tab）。
  shell 提示符与裸 shell 无差（零侵入），靠这两行告诉用户 rysh 在运行，避免「打印一行就退出」的观感。
- **退出**：改 `screen.go:333 Reset()`，去掉 `ExitAltScreen` 与 `ResetScrollRegion`，只保留 `\x1b[0m`（复位颜色）+ 显示光标 `\x1b[?25h` + 必要时换行到干净行。**不清屏**，让 rysh 的屏上内容留在主屏滚动历史里。
- **崩溃清理**：`run()` 的 panic recover defer 简化为复位颜色/光标、不碰备用屏；不再需要"退出备用屏 + 清颜色 + 重显光标"那一套。
- **RIS（`\x1b c`）复位**：当前检测到 RIS 会"重新进备用屏并重建界面"（`工作计划.md` 2026-08-27）。主屏下 RIS 由终端自身清屏，ryshell 只需在 RIS 后**重绘提示符 / 当前 AI 输入行**即可，不重进备用屏。

### 3.2 shell 模式：零侵入 + 启动横幅

- shell 模式保持 PTY 字节级透传，**不修改用户 PS1**、不替代用户任何 shell 配置（避免与 oh-my-zsh / starship 等主题冲突）。
- 提示符标记（2026-08-31 修订，`[tui] prompt_marker` 缺省 `auto`，`"off"` 恢复本节的原零侵入行为）：零侵入与常驻标识的折中——① 标题层（所有 shell）：运行期间 rysh 接管终端标题（`rysh · <model> · session <id>`），过滤子 shell 的 `OSC 0/2` 标题序列（纯带外，其余透传字节不变），退出时尽力恢复原标题；② bash 层：向子 shell 环境导出 `PROMPT_COMMAND` 一行（bash 从环境导入并在每个提示符前执行），暗色 `(rysh) ` 前缀幂等前置 PS1——不改用户配置；**尽力而为**：用户自己的 rc（starship/direnv/nvm）若自己赋值 `PROMPT_COMMAND`，用户值胜出、标记静默退场，绝不破坏用户提示符（`--rcfile` 方案实测只被非 login 交互式 bash 遵循，login shell 下被静默忽略，故弃用）；③ zsh 层：zsh 无 rcfile 参数、无 `PROMPT_COMMAND`，唯一的环境注入点是 `ZDOTDIR`——子进程指向私有临时目录（只含单个 `.zshenv`），该文件注册 precmd 钩子（暗色 `(rysh) ` 幂等前置提示符，包在 `%{...%}` 非打印标记里）后把 `ZDOTDIR` 指回用户真实 dotdir（外层 `ZDOTDIR` 或 `$HOME`）并代跑用户的真 `.zshenv`；`.zprofile`/`.zshrc`/`.zlogin`/补全缓存照常解析、不改用户配置；钩子先于用户 rc 注册，用户 precmd 钩子（starship/powerlevel10k）整体重写提示符时用户胜出、标记静默退场；临时目录退出时删除（实测坑：zsh 认 envp 里**第一个**同名 `ZDOTDIR`，外层导出的值必须先剔除；`ZDOTDIR` 置空串会被 zsh 误判为新用户而跳过 `$HOME` 启动文件，故只能整体替换、不能置空）；④ fish 等无可靠注入点，只做标题层，提示符前缀走 `RYSH_INSIDE` 条件化 opt-in（用户自己的 rc）。
- 辨识度来源：① 用户本就是手动 `rysh` 启动的；② 启动横幅（两行，含切换键提示）；③ AI 模式的 `[AI]` 提示符；④ 提示符标记（缺省开启，见上）；⑤（fish 等其他 shell 的提示符前缀，用户自行配置）按 `RYSH_INSIDE` 环境变量条件化改自己的提示符。
- 透传路径本身不变，仅去掉"全屏程序期间释放/恢复滚动区与状态行"中与状态栏/滚动区耦合的部分（见 3.4）。

### 3.3 AI 模式提示符 + 末行 spinner

- AI 提示符行渲染 `cwd` · `model` · `[AI]:`（例如 `~/proj  hy3/hy3  [AI]: ▌`）。以 `[AI]: ` 而非 `[AI] ` 收尾，更像自然语言输入框（`:` 暗示"你说 / 我答"的对话感）。
- `spinner` / 状态文本**不放提示符内**，改为流式期间在内容**末行**追加状态行：
  `⠧ 正在思考…` → 完成后改为 `✓ 完成` 或直接擦除。
- 主屏下末行随终端自然滚动，无需 DECSTBM 钉行；若用户已滚上去看不到，属正常终端行为。

### 3.4 去状态栏 + 去滚动区

- 删除状态栏渲染：`ShellStatus` / `AIStatus` / `OnStatus` / `paintStatusLocked`（`screen.go`、`main.go`）相关调用移除。
- 删除所有 `screen.ScrollRegion(max(h-1,1))` 与 `ResetScrollRegion` 调用（`main.go` 多处：约 `:626`/`:786`/`:1237`/`:1246`/`:1260`/`:1416`）。内容像普通终端一样整屏自然滚动。
- **`leaveAI` 简化**：当前为把 shell 提示符对齐到第 23 行（状态行之上），先把光标移到 `max(h-1,1)` 再 `\r\n`。主屏无钉行后，直接让 shell 在底部自绘提示符即可，去掉该特殊定位。

### 3.5 `Detector.Alt`：只保留记录暂停

- **保留**：检测 PTY 流里的备用屏私用模式（`?1049h` 进 / `?1049l` 出，覆盖 `?47`/`?1047`），进全屏程序时 `rec.Pause()`、退出时 `rec.Resume()`，避免 vim 的按键与重绘被记成 shell 命令/输出污染 `~/.rysh/sessions` 日志。
- **删除**："检测后重新进备用屏 + 重建界面"的自愈补偿逻辑——主屏下 vim 退出 `\x1b[?1049l` 回到主屏正好，ryshell 透传即可，无需重建。

### 3.6 统一时间线回放（含 shell 对话）

- **会话历史 = 自然语言对话 + shell 对话交织成的一条连续时间线**。`buildTimeline`（`main.go:1934`）已把 shell events 与 AI `hist` 按时间戳合并喂给模型——回放应复用同一概念，但当前 `renderHistoryReplay`（`session_cmds.go:269`）只吃 `[]ctxMsg`（仅 AI），**漏掉了 shell 对话**。
- 新回放渲染函数改为消费**统一时间线**，逐条渲染：
  - `usr` → `─── 用户 ───`
  - `asw` → `─── 助手 ───` + markdown
  - `shk` → `─── $ <cmd> ───`（高亮）
  - `shl` → shell 输出（默认保留原色，见 §4）
- **两个模式都回放**：当前 shell 模式 `/cs` 直接 `st.ToShell()` 不回放（`main.go:1449`）；改为无论落在 AI 还是 shell 模式，`/cs` 落地都先打分隔行 + 尾部回放，再画对应提示符。
- **切换分隔行**（用户认可的建议）：每次切换打印一行，例如
  `──── 切换到会话 <id> · 共 M 条消息 · <time> ────`
  放在回放之前，使连续的滚动历史里能定位每个会话起止（主屏下 scrollback 是跨会话的连续缓冲，分隔行必要）。

### 3.7 尾部块原子回放（高性能，不全量渲）

- **问题**：历史可能极长；先全量渲染再截尾 N 行太慢（`asw`/`rea`/`shl` 都是流式多记录写入，全量渲代价高）。
- **算法**：
  1. **只从日志文件末尾读最后 K 条原始记录**（`seek` 到文件尾往前读，不解析整文件；`K` 取能稳超 N 行的常量，如 `replayTailLines*4` 或固定 400）。统一时间线在文件里已按追加顺序交织 shell+AI，无需再合并两份列表。
  2. **从尾向前合并「连续同 kind 记录」为块**。原因：已确认 `rea`/`asw`（`main.go:2029`/`:2035` `OnText`，逐 delta 写）以及 `shl`（输出循环逐块写）都是**流式多记录**——一个推理块 = 多条 `rea`，一个回答 = 多条 `asw`。若按单条记录截断会把一个回答从中间切断。合并后一个块 = 一个逻辑单元（一段推理 / 一个回答 / 一段 shell 输出）。
  3. 从最后一块向前逐块渲染（按 kind 上样式），累加行数；累计 ≥ N 即停，但**整块取舍，绝不切块**。
  4. 反转回正序，头部补 `… 更早的对话已省略`（精确条数可选，数全文件不划算，省略即可）。
- 效果：历史再大也只渲尾部少量块，不卡；且天然满足"推理/回答不跨类型截断"。
- 常量：`replayTailLines`（默认建议 200，可配置）。

### 3.8 markdown 表格 reflow 与滚动历史

> 标注（实现期复核）：ryshell **没有 GFM 表格渲染器**——AI 回复的 markdown 以纯文本/ANSI 方式流式输出，不存在"表格按列对齐、后续行改列宽导致老行被重写"的路径。因此本节讨论的"表格 reflow 列宽不一致"在本项目中 **N/A**（对应 §7.10 的"表格渲染器只重绘可见尾部"也无需实现）。若未来引入真正的表格渲染，再回到本节的滚动偏移方案。

- 主屏下 AI 渲染 markdown 表格时，新行导致老行列宽变化、老行被重写（光标定位覆盖）。要点：
  - 滚动历史缓冲区**只在"一行从可见区顶部滚出时"存入字符快照**，且一旦存入**只读**——应用层无法改写已滚进历史的行。
  - 故：仍在**可见区**内的老行可被重写加宽（只改当前显示，不影响历史）；已滚进历史的早期行冻结在最后宽度。**不会破坏缓冲区内容**，仅历史中可能出现"前列窄、后列宽"的轻微不一致——这是所有终端表格/进度条 reflow 的固有现象（glow、各类 TUI 皆如此），非数据损坏。
  - 实现注意：表格渲染器须**只重绘仍可见的尾部**并跟踪"已滚出多少行"，不能假设能从固定绝对行号往上重写（无 DECSTBM 钉行了）。
  - 对比当前 alt 屏：alt 屏**根本没有历史**，表格超 24 行时早期行直接丢失；主屏反而能 `Shift+PgUp` 看全表，只是历史里列宽可能不一致。故主屏对"看完整表格"更优。

### 3.9 多会话切换（v6）

- 当前切换做 `ClearScreen` 全屏重绘；主屏下改为：打印分隔行 + 尾部回放 + 画提示符，**不清除**已有内容。
- 连续 scrollback 跨多个会话，靠 §3.6 的分隔行区分。

## 4. 日志样式说明（已实现，回放需注意）

回放渲染需知：日志**并非全纯文本**，按 kind 不同：

| kind | 写入经 | 日志是否含样式 |
|---|---|---|
| `shl`（shell 输出） | `SanitizeStream` | **保留 SGR 颜色**（剥光标移动/擦除，留颜色） |
| `asw`（助手回答） | `SanitizeStream` | 保留 SGR（通常无，markdown 本无 ANSI） |
| `rea`（推理） | `SanitizeStream` | 保留 SGR |
| `shk`（命令） | `aiui.Sanitize` | **纯文本**（剥所有 ANSI） |
| `usr`/`noti` | `aiui.Sanitize` | 纯文本 |

- 回放时 `shl` **默认保留原色**（历史与实时一致最不意外）；如需安静风格，渲染端先把 `shl` 的 SGR 剥掉再套暗色即可（渲染端可控）。
- 实时显示与日志是两条路：shell 透传把 PTY 原始字节（含颜色+光标移动）直接转发上屏；日志是"去光标移动、留颜色"的副本。

## 5. 不受影响的部分

- **模型上下文喂送**：`buildTimeline` + `trimShellEvents` + `trimHistory(maxHistory=120)` 逻辑完全不动，本方案只改屏幕回放渲染。
- **会话日志格式 / kind 命名**：不改（kind 重命名为 `shq/sha/aiq/...` 的讨论**延后**，本方案不做；项目未发布，无旧会话兼容问题，但改名属洁癖型优化，单独处理）。
- **嵌套 rysh 守卫**：`RYSH_INSIDE` 检测不变。
- **会话磁盘存储**：`~/.rysh/sessions/<id>/messages.log` 结构不变。

## 6. 风险与注意

1. **无"始终钉住"的模式指示**：去掉状态栏后，AI 回复很长、屏幕滚上去时 `[AI]` 提示符会滚进历史，不再钉底部。属预期内的小退化（普通终端聊天工具皆如此）。
2. **shell 模式标识**：初版零侵入（仅启动横幅 + 手动启动 + AI 模式 `[AI]` 辨识，与裸 shell 提示符无差）在实践中被用户误判为「rysh 已退出」，2026-08-31 起由提示符标记（§3.2 修订：终端标题接管 + bash `PROMPT_COMMAND` 环境前缀 + zsh 私有 `ZDOTDIR` precmd 钩子，缺省开启、`prompt_marker = "off"` 可回退原行为）承担常驻标识；fish 等其他 shell 的提示符前缀仍走 `RYSH_INSIDE` opt-in（见 README「提示符标记（常驻标识）」）。
3. **表格历史列宽不一致**：见 §3.8，固有现象，非缺陷。
4. **退出后光标位置**：若 rysh 退出时光标停在中部（如 AI 模式末行），需在退出路径补换行，避免外层 shell 提示符接在奇怪位置。
5. **`leaveAI` / aiui 渲染假设**：须移除对"固定滚动区 + 状态行之上"的坐标假设，改为跟随终端自然滚动；重绘提示符改用"移到行首 + 清行"。
6. **`[tui] cursor_style` 随之失效**：状态栏是唯一的 DECSCUSR 发送点（`ShellStatus` 内联 `CursorStyleSeq`），栏没了就没有发送者。配置键仍留在 `TUI` 结构体里解析——解码器本就忽略未知键，删掉也不会让旧配置报错，保留只是为了不改动已文档化的配置面；该键不再被读取，取值也从不校验（历史上同样不校验，未知值只会落到缺省 bar）。README 已标注"已失效"，`TestTUIPrefs` 断言 `block` / `default` 两种取值都不得发出任何 DECSCUSR。
7. **AI→shell 重注入按回显校验**：Windows 上 ConPTY 还在处理 `ResizePseudoConsole` 时写进子 PTY 的字节可能被整条丢掉。实测（bash 子进程、80×24、无负载、12 次切换）约 1/5～1/3 的切换会丢重注入行的首字符——shell 行上成了 `cho ABXCDE`，回车即 `command not found`；关掉校验重跑 10 次，3 次复现。"等提示符重绘稳定再注入"的静默期判据压不住它：25ms 无输出既可能是重绘已完成，也可能只是两次重绘之间的空隙（trace 显示丢字与"注入前恰好落了 3 段输出"一一对应，落 4 段与只落 1 段都不丢）。现改为 `cmd/rysh/resync.go`：注入后在 300ms 内到子进程输出流里核对整行回显，未落全就清行重打（readline 系发 `^U ^A ^K` 三键，只认 `^U` 的 shell 发 `^U`；上限 2 次，再多就是可见的结巴）。清行受同一丢字影响：重试紧跟在一次失败校验之后，正是写入最可能掉字的时刻，只发 `^A ^K` 时掉 `^A` 会让重打接在半截行尾巴上（合成 `cho ABXCDEecho ABXCDE`，看着像修好了，回车却是 `command not found`）。三键各自独立：`^U` 从光标往回删、`^A ^K` 从行首往前删，任缺其一仍留下可用组合，故一并发送；该不变量由 `TestResidualClearSurvivesALostByte` 逐字节穷举锁定（前提是光标在行尾——刚打完这一行——此时三键任缺一字节都能清空）。反向的 shell→AI 清行不适用同一组合：那里光标可能停在行中，缺 `^K` 就会留下后半截，且该路径不做 resize（`applySize` 只在启动与 SIGWINCH 时调用），实测未出现丢字，故保持 `^A ^K` 不变。校验只会把"其实成功了"误判成"要重打"，代价约 450ms 且半行由 shell 自己擦掉；反向漏判（重排把旧行重新打印成同样文本）最坏退回本项修复前的行为，不引入新的损坏形态。末轮探针（执行校验改为行首锚定，被丢弃的重试副本蒙不过去）12/12 无丢字，其中 2 次走了重打；`TestCursorPreservedAcrossModeSwitch` 20/20 通过。
