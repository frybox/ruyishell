# 需求分析

> **2026-08-30 现状同步（屏幕模型）**：本文是需求阶段的记录，其中关于**可视反馈**的设想（§3 的 AI/SH 模式字样、光标形状联动、状态栏模式 chip）已由[主屏方案](./主屏方案.md)取代：rysh 只用主屏、无底部状态行、不改终端光标形状。§7 里以"备用屏/DECSTBM 冲突"论证的非目标条目，其结论仍然有效但理由已换（见该条括注）。§8 的三条 TUI 展示增强规划项（向上滚动时把草稿行钉在底部、一键直达底部、块状展示 shell 命令与 AI 回复）也一并作废：回看改用终端原生 scrollback（`Shift+PgUp` / 滚轮），rysh 不做应用级视口、钉行与独立滚动区。需求层面的目标（§1、§2 两种输入模式、§4 会话模型等）不受影响。

## 1. 总体目标

提供一个以 shell 为默认、AI 可一键切入的交互式 shell（命令名 `rysh`），把"shell 效率高、AI 灵活"两种能力放在同一行输入中，并让 shell 的输入输出自然成为 AI 会话的上下文。支持 Linux、macOS、Windows 三平台：shell 部分各平台包装本机默认 shell（Linux/macOS 为登录 shell，Windows 为 PowerShell 等，见 §6 PTY 模型）。

## 2. 两种输入模式

### 2.1 Shell 模式（默认）

- 用户输入直接交给登录 shell 子进程处理，行为与普通终端一致。
- 输入输出在 shell 模式下走"透传"路径，保持原生速度和体验。

### 2.2 AI 模式

- 用户输入作为自然语言请求，交给 agent loop 处理。
- agent 可以流式回复、可以调用工具（执行 shell 命令、读写文件等），工具的输入输出也进入会话上下文。
- 当前任务处理完后**默认留在 AI 模式**，因为用户可能追问；随时可以一键切回 shell。

## 3. 模式切换（交互核心）

### 3.1 基本原则

**"切换模式"与"清空输入"是两个正交操作，绑到不同的键上。**

| 键 | 语义 | 绝不动的东西 |
|---|---|---|
| 行首空格（仅空输入） | 切换模式（快切，双向） | 无输入，无影响 |
| Shift+Tab（任意状态） | 切换模式（通用切换） | 输入缓冲 + 光标位置原样保留 |
| Esc | 只清空输入缓冲 | 不切换模式 |
| Ctrl+Z（规划） | 撤销，找回被 Esc 清空的内容 | — |
| ↑ / ↓（Ctrl+P / Ctrl+N）（规划） | AI 模式下轮换已提交的用户输入，选中即回填草稿 | 不切换模式 |

### 3.2 错误输入恢复

- **AI 模式下误输了 shell 命令**：按 Shift+Tab → 文本原样、光标原位 → 回到 shell 模式 → 直接回车执行。零重打。
- **AI 模式下误按 Esc**：只清空文本、仍留在 AI 模式；后悔可 Ctrl+Z 找回。不会既切模式又删文。
- **shell 模式下误输了自然语言**：按 Shift+Tab → 文本原样 → 进入 AI 模式 → 回车。零重打。

### 3.3 视觉反馈（模式必须一眼可辨）

- **提示符**：AI/SH 字样随模式切换。
- **光标形状**：
  - Shell 模式：闪烁竖线/I 形光标（对应 vim insert 心智）。
  - AI 模式：实心方块光标（或慢速脉冲方块），配独立强调色（如洋红/紫）。
- **可选增强**：输入区着色、状态栏模式 chip（滚动离开提示符后仍可辨）。

## 4. 会话与工作目录

- **会话不绑定项目目录**。agent 会话不绑定到某个操作系统目录上。
- **cwd-as-data**：每个 shell 命令、每条 AI 请求、agent 的每次工具调用都携带自己的当前工作目录。
- **cwd 跟踪**：shell 模式下用户在登录 shell 里 `cd` 切换目录后，**ruyishell 本身也要能拿到这次切换**，使后续 AI 请求/命令在正确的目录下执行。
- **环境变量跟踪**：登录 shell 子进程的环境变量变化（export 等），ruyishell 最好也能跟着同步。
- **上下文带出处**：AI 会话能看到每条 shell 命令"在哪个目录、什么命令、stdout/stderr、退出码"。

## 5. 大模型配置

### 5.1 配置文件

- 位置：`~/.rysh/config.toml`。
- 采用 **provider → model 两级配置**：先定义 provider（本地 llama-server / OpenAI / Anthropic / Grok / GLM 等），再在每个 provider 下配置可用的模型与默认模型。
- 支持环境变量/密钥引用，密钥不写死在配置文件里。

### 5.2 模型切换

- AI 模式下提供 `/model` 命令切换当前模型。
- 切换即时生效，可用于当前及后续会话。

## 6. 架构性需求

- **PTY 模型**：ruyishell 本身持有 pty master（Windows 为 ConPTY）；clone 出子进程，子进程持有 pty slave 后执行默认 shell。Linux/macOS 取用户登录 shell（`$SHELL -l`）；Windows 无登录 shell，按 `pwsh` → `powershell` → `cmd` 探测并加载其 profile。
- **Shell 模式**：输入输出直接交给登录 shell 处理。
- **AI 模式**：ruyishell 使用 agent loop 处理自然语言输入。
- **实现语言：Go**。理由：静态单文件交叉编译为 Go 内置能力、终端/PTY/并发生态成熟、团队更熟；provider 层内置极简 OpenAI 兼容 SSE 客户端（见[架构设计](./架构设计.md) 3.5），TUI 直接写 ANSI/PTY 字节流，不引入 bubbletea 之类的全量渲染框架（一屏一流，见 ADR-7）。生态查证见[技术选型调研](./技术选型调研.md)。

## 7. 非目标（明确不做）

- **多任务**：不做多窗口/多终端复用，交给 tmux 等系统。（注：v6 的进程内多会话不属此列——它是同一个终端、同一个 pty 上切换 AI 会话流，不创建第二个终端、不支持并行同屏，见架构设计 §3.10。）
- **嵌套 rysh**：不支持在 rysh 内启动交互式 rysh。两层 rysh 共用同一终端时，模式切换键（Shift+Tab/首空格）会互相冲突——内层的切换键会被外层吞掉，外层以为还在自己的输入里，内层却收不到。（[主屏方案](./主屏方案.md)后备用屏与 DECSTBM 滚动区都已取消，当初并列的另两条冲突理由不再存在，但键位冲突这一条足以否定嵌套。）行为约定：外层 rysh 在子 shell 环境注入 `RYSH_INSIDE=1`，内层 rysh 检测到该标记且不带版本参数时在创建 pty 前直接拒绝并提示（退出码 1）；`rysh -v` 等不创建 pty 的命令行形式在 rysh 内仍可用。
- **模型自进化**：不考虑。
- **强绑定本地模型**：不强求。
- **替代 wukong**：两个项目独立演进。

## 8. 后续可考虑（规划项，非首版）

- TUI 展示增强（参考 grok 的终端体验）：
  - 向上滚动内容时，用户最新输入始终固定在底部（草稿行固定，会话区独立滚动）；
  - 一键直达底部；
  - 更好的流式渲染、块状展示 shell 命令与 AI 回复。
- Ctrl+Z 撤销（找回被清空的输入）。
