# 产品方向

## 一句话定位

**ruyishell**（命令行命令：`rysh`）是一个以增强本机 shell 的 AI 交互体验为目标的新一代交互式 shell——以 shell 为默认、AI 为副驾，在同一行输入中一键切换两种模式。

## 核心哲学

- **Shell 优先，AI 随叫随到**。默认停在 shell 模式，输入即执行，保持 shell 的低延迟与高效率。需要 AI 时一键切到 AI 模式，用完可以继续留在 AI 模式（便于追问），也可以一键切回 shell。
- **模式切换，内容不丢**。切换模式绝不触碰输入缓冲和光标位置：行首空格 / Shift+Tab 只切模式不改文字；Esc 只清文字不切模式。错误输入（AI 模式下敲了 shell 命令、shell 模式下敲了自然语言）只需按一次切换键原地改目的地，零重打。
- **人机接力**。shell 事件和 AI 事件在同一个事件流中混排，AI 看得见用户手动执行了什么、输出了什么；用户随时可以接手 agent 的工作，也可以把工作交回给 agent。
- **cwd-as-data**。会话（任务）不绑定到某个项目目录；每个命令/事件携带自己的当前工作目录，目录随时可换，历史可回放，AI 上下文自带出处。
- **本地优先，但不强求**。不强求本地模型，支持本地与云端各类 provider，模型按需配置、随时切换。
- **不考虑模型自进化**。ruyishell 只做交互体验，模型能力演进交给模型提供方。

## 与 Warp 的对比

**Warp** 是一个独立 GUI 终端应用（Rust + GPU 渲染，闭源），替换用户的既有终端；ruyishell 是跑在任何现有终端里的 TUI 程序。定位差异一句话：**Warp 是"换掉你的终端"，ruyishell 是"不换终端、增强你的 shell"**。

**共同点**（两个项目面向同一问题）：

- Shell-first、AI 内嵌：用户真实 shell 照常运行，AI 是嵌在终端工作流里的副驾驶，而非纯聊天 UI。
- 自然语言进入终端输入流，流式 AI 回复，并可生成、驱动命令执行。
- Agent 能执行 shell 命令，并把结果回灌为后续回答的依据。
- 最近的 shell 历史 / 命令输出成为 AI 上下文的一部分。
- 对 AI 输出做富渲染；都面向多平台（macOS/Linux）的开发者。

**差异点**：

| 维度 | ruyishell | Warp |
|---|---|---|
| 产品形态 | TUI 程序，跑在任何现有终端内（xterm/iTerm/Ghostty/tmux 等） | 独立 GUI 应用，自绘窗口，替换既有终端 |
| 架构 | 薄层：pty 包装 + shell 模式字节级透传，无渲染框架（一屏一流） | 全量终端模拟器：GPU 渲染重实现屏幕，自定义 UI 工具链 |
| AI 入口 | 同一行输入一键切模式（Shift+Tab / 行首空格），草稿零重打、跨切换存活 | 旁路入口：自然语言识别 + 斜杠命令 + 独立 AI 面板，无"模式"概念 |
| 模型 | BYO provider：任何 OpenAI 兼容端点（本地/云端），`/model` 热切换，无账号 | 绑定 Warp AI 云服务，需 Warp 账号，有额度限制 |
| Agent 能力 | 起步刻意简单（bash 围栏块循环 + 4 轮上限）；M7 起换成原生 function calling 的多步循环：工具集 + 权限审批门 + 超时转后台 job + 子任务委派，**无轮数上限**（靠死循环守卫与 token 预算收口，见[agent执行流程设计](./agent执行流程设计.md)）；仍不做 MCP 与沙箱 | 更完整：多步自主 Agents、MCP 支持 |
| 输出渲染 | shell 输出原样透传（全屏程序零干扰），仅 AI 回复做 markdown 渲染 | 全输出 block 化：带退出码/耗时等元数据，表格/diff 富渲染 |
| 云与协作 | 无云、无账号、无遥测；会话日志为本地 append-only JSONL | Warp Drive 云同步：block 分享、workflow 复用、团队协作 |
| 开源 | 开源 Go 项目，可自托管 | 闭源商业产品 |
| 范围哲学 | 刻意收窄：不做多窗口（交给 tmux）、不做多任务 | 全功能终端产品套件（主题、workflow、企业功能等） |

**关键分界**：

- **侵入程度**：Warp 要求迁移到它的终端；ruyishell 不碰既有终端与 shell 配置，退出后把终端原样还给用户——对"不想改变工作流"的用户正是卖点。
- **模型自由**是 ruyishell 的核心差异化：自带 key、可全本地、直连国内 OpenAI 兼容厂商（见[技术选型调研](./技术选型调研.md)）；Warp 的 AI 是自家云服务（账号 + 额度 + 数据过云）。
- **块体系**（退出码捕获、耗时、block 分享、workflow）是 Warp 领先项；ruyishell 侧属"薄层透传"架构的刻意取舍（相关能力已被实证为跨 shell 硬阻塞），不是缺口。
- **模式切换零摩擦**（同一行输入、一键切换、内容不丢、AI 看得见 shell 历史、共享同一屏幕流）是 Warp 没有的交互。

> 口径备注：Warp 侧内容基于公开资料（含其 2025 年起 Agents / MCP / 本地模型等进展），细节以 warp.dev 最新公告为准。

## 目标用户

- 日常大量使用终端的开发者、运维、数据工程师
- 想用 AI 辅助、但不想改变既有 shell 工作流的人
- 对"每条 AI 请求都要加前缀 / 换行 / 另开窗口"感到不便的人
- 想自己开车、让 AI 当副驾（而非全权委托）的人

## 价值主张

- **零摩擦**：shell 模式零额外动作，AI 模式一键到达，切换不丢内容。
- **上下文自然**：shell 输入输出自动成为 AI 会话的一部分，无需手动复制粘贴。
- **目录无关**：会话不绑定项目，你在哪个目录，命令就在哪个目录执行；agent 的上下文也跟随 cwd。
- **模型自由**：本地/云端、各家 provider 任意切换，配置在 `~/.rysh/config.toml`。
- **轻量无侵入**：以交互体验为目标，不做多任务（交给 tmux），体积/复杂度可控。
