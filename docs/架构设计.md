# 架构设计

## 1. 技术选型

- **实现语言：Go**
  - provider 层内置一个极简 OpenAI 兼容 SSE 客户端（`internal/provider`），直接对接各家 `/chat/completions` 与 `reasoning_content` 扩展；不引入官方 SDK，避免第三方依赖漂移，换模型/换协议只改配置。
  - 终端控制与渲染不依赖大型 TUI 框架：直接写 ANSI/PTY 字节流（`internal/screen` 提供原语，`charmbracelet/x/ansi` 只用于光标移动与行清理），避免全量重渲染框架对透传 shell 的干扰。
  - 静态单文件交叉编译是 Go 内置能力（`CGO_ENABLED=0`），分发最省事；编译产物体积不是重点。
  - 团队对 Go 更熟，迭代更快。生态查证见[技术选型调研](./技术选型调研.md)。
- **PTY**：跨平台统一用 `aymanbagabas/go-pty`——Unix 底层即 `creack/pty`，Windows 走 ConPTY，一套 API 覆盖三平台；`creack/pty` 本身是纯 POSIX（Windows 编译不过），Windows 侧若要自研才需 `UserExistsError/conpty` 这类 ConPTY 库。
- **TUI**：首版确定为"透传共享屏 + 一屏一流"，不使用 bubbletea 之类的全量渲染框架（shell 侧字节级透传与 vim/less 全屏程序不受任何框架干扰）。

## 2. 进程模型

```
┌───────────────────────────────┐
│  ruyishell (rysh)             │
│                               │
│  ┌────────────┐               │
│  │ pty master │◄──────────────┼── 键盘输入 / 屏幕输出
│  └─────┬──────┘               │
│        │                      │
│  ┌─────▼──────┐               │
│  │ 输入路由    │               │
│  │ (模式状态机)│               │
│  └─────┬──────┘               │
│        │                      │
│  ┌─────┴───────────────────┐  │
│  │  shell 模式 → 登录 shell   │  │
│  │  AI 模式 → 草稿行（M2，    │  │
│  │    M3 起接入 agent loop）  │  │
│  └─────────────────────────┘  │
└───────────────────────────────┘

  ┌───────────────────────────────┐
  │ 子进程 (clone)                │
  │  ┌───────────┐                │
  │  │ pty slave │ ←→ 默认 shell   │
  │  └───────────┘  (取法见 §3.1)  │
  └───────────────────────────────┘
```

- **rysh 持有 pty master**；clone 出子进程，子进程持有 pty slave 并执行默认 shell（三平台取法见 §3.1）。
- shell 模式：输入输出直接交给登录 shell，保持原生速度与行为。
- AI 模式：rysh 截获输入，由 agent loop 处理；agent 执行 shell 命令时复用同一套执行通道。
- **一屏一流**（v4，主屏方案修订）：shell 与 AI 在同一块屏幕、同一条终端流上连续会话——rysh 全程留在终端**主屏**，子 pty 占满 H 行、无 DECSTBM 滚动区、无底部状态行，历史由终端原生 scrollback 承载；进入/退出 AI 不切 alt screen、不清屏、不重建 shell 画面，只在原地替换提示行。（v4 原设计的"子 pty 高度 H-1 + rysh 独占状态行"已被[主屏方案](./主屏方案.md)取代。）

## 3. 核心模块

### 3.1 PTY 层
- 创建 pty master/slave（Windows 为 ConPTY），clone 子进程挂接 slave 并 exec 默认 shell。
- 默认 shell：Linux/macOS 取用户登录 shell（`$SHELL -l`）；Windows 无登录 shell，按 `pwsh`（PowerShell 7）→ `powershell`（内置 5.1）→ `cmd` 探测，并加载其 profile（PowerShell 交互启动自动加载 `$PROFILE`；pwsh 7 另有 `-l` 登录参数）。
- 负责终端尺寸（SIGWINCH）、信号转发、原始终端模式管理（Windows 经 ConPTY 的按键/信号语义不同）。

### 3.2 输入路由 / 模式状态机
- 维护当前模式：`Shell` / `AI`（`internal/mode`）。
- 识别模式切换键：行首空格（仅空输入）、Shift+Tab（任意状态，默认键，CSI Z）；默认键可经 `mode_switch` 换为 `ctrl-tab`（兼容 xterm/kitty 三种键码编码）/ `ctrl-space` / `ctrl-backslash`。
- **shell 模式共享屏**（主屏方案修订）：rysh 不保留任何行——子 pty 占满终端高度 H，无 DECSTBM 滚动区、无底部状态行；`internal/screen` 只提供光标/颜色复位与 alt-screen 检测，全屏程序进入时暂停按键记录、退出时恢复，不做滚动区释放/恢复与界面重建。
- **AI 模式（v4 一屏一流）**：进入 AI 模式不切 alt screen、不清屏、不动滚动区、不改终端光标形状；AI 编辑器的草稿与多轮会话（`internal/aiui`）常驻进程，跨模式切换存活。shell 与 AI **共用同一条输入行**：进入 AI 时 shell 未提交的命令带进 AI 草稿（shell 侧清空该行：带行编辑器的 shell 以 ^A+^K、纯 shell 以 ^U），退出时 AI 草稿回注到 shell 命令行（不带回车），文本与光标位置随切换延续（shell 光标所在列带进 AI 草稿，切回时按列差补发左方向键把 shell 光标回注到同一列，仅对带行编辑器的 shell）。AI 模式下 pty 输出暂不转发（缓冲），仅记录到会话日志，返回 shell 时一次性刷新到屏幕，保证会话流完整；返回后用裸 `\r` 让 shell 自己重绘提示行（rysh 不回放任何 shell 画面）。
- 视觉反馈联动（主屏方案修订）：无底部状态行、光标形状不再联动；模式与身份信息只出现在滚动流里——启动横幅 `rysh · <model> · session <id>` 与 AI 提示行 `cwd · model · [AI]:`（模型名在此行，`/model` 切换后重绘即更新）。
- **任务锁**：AI 任务流式输出期间禁止切换模式（切换键被忽略并提示），只有 `^C` 可终止任务。

### 3.3 执行通道
- shell 模式：输入写入 pty master，输出透传。
- AI 模式的 agent 工具执行：向同一登录 shell / 或独立命令执行器发起 shell 命令，**记录 cwd、stdin、stdout、stderr、exit_code**。

### 3.4 Agent Loop
- 接收 AI 模式下的自然语言输入，组装会话上下文，调用当前 provider/model 生成。
- 流式输出；支持追问（留在 AI 模式）。
- 支持工具调用：执行 shell 命令、读写文件等，结果回灌上下文。
- `/model` 命令切换模型，即时生效。
- **M7 重设计**（原生 function calling + 完整工具集 + 审批 + 长命令后台化 + 上下文压缩）：见[agent执行流程设计](./agent执行流程设计.md)。
- **M7.7 管理者模型**：AI 模式顶层 run 是管理者（manager），上下文当作最稀缺资源守财；重活一律委派工人子智能体（独立上下文的 engine run），管理者负责派遣、监控、判疯即停、验收与总结；run 在自身子任务运行中不能结束（引擎先提醒一次，再自己等待并把报告回喂，模型验收后收尾）——见[agent执行流程设计 §16](./agent执行流程设计.md)。

### 3.5 Provider 抽象
- **provider → model 两级配置**，读 `~/.rysh/config.toml`。
- provider 层：本地 llama-server（OpenAI 兼容）、OpenAI、Anthropic、Grok、GLM 等。
- model 层：每 provider 下多个模型 + 默认模型。
- 使用成熟的 provider 处理库，屏蔽各家协议差异。
- OpenAI 兼容层已具备原生 function calling 线型协议（M7.1）：tools 定义请求字段、assistant `tool_calls` / `role=tool` 消息、流式 `delta.tool_calls` 装配（index 分道、arguments 增量拼接）、`stream_options.include_usage` 尾块、模型级 `tools` 开关与 400 拒工具的 `ToolsUnsupportedError`（M7.2 已接线：engine 经 `StreamClient` 接口驱动，400 自动降级围栏协议）。

### 3.6 会话与上下文（cwd-as-data）
- **会话不绑定目录**；每个事件携带自己的 cwd。
- **cwd 跟踪**：登录 shell 子进程 `cd` 后，rysh 需要拿到切换结果。方案（择一或组合）：
  - 通过 `\w`/`pwd` 感知（PS1 注入 / OSC 报告）；
  - 拦截/包装 `cd`（hook 到 PROMPT_COMMAND）；
  - 定期或事件驱动地查询子进程 cwd（`/proc/<pid>/cwd`，Linux）。
  - Windows：在 PowerShell `$PROFILE` 的 `Prompt` 函数注入 OSC 7 上报 cwd（无 /proc 等价物；cmd 只能靠 AutoRun 全局注入，侵入且脆弱）。
- **环境变量跟踪**：检测子进程环境变化并同步到 rysh 侧，使后续命令/AI 请求继承正确的环境。
- 事件流：shell 事件（命令 + 输出 + 退出码 + cwd + 时间戳）与 AI 事件（请求 + 回复 + 工具调用）在**同一条流**中混排，即"shell 输入输出成为 AI 会话的一部分"。

### 3.7 配置
- `~/.rysh/config.toml`：provider/model、默认 shell、按键绑定、TUI 偏好。
- 密钥经环境变量引用，不落盘明文。

### 3.8 TUI（一屏一流，v4）
- **shell 模式**：透传共享屏（主屏方案修订：子 pty 占满 H 行，无底部状态行、无 DECSTBM 滚动区，历史进终端原生 scrollback）、模式指示（启动横幅 `rysh · <model> · session <id>` + 提示符标记：终端标题接管 + bash 提示符 `(rysh)` 前缀（`PROMPT_COMMAND` 环境导出）+ zsh 提示符 `(rysh)` 前缀（私有 `ZDOTDIR` 的单个 `.zshenv` 注册 precmd 钩子后指回用户真实 dotdir），主屏方案 §3.2 修订，`[tui] prompt_marker = "off"` 可回退无标识纯透传）、alt-screen 检测（全屏程序进入时暂停按键记录、退出时恢复，不做滚动区/状态行释放恢复与界面重建）；启动到登录 shell 首个输出之间在末行就地显示 `⠋ 启动中...`（首个输出到达或切进 AI 模式即擦除让位，spinner 期间隐藏的光标随之恢复显示）。
- **AI 模式**（同一屏幕、同一流）：AI 提示行用 bash-PS 风格可配置（`[ai] prompt`，支持 `\w`/`\u`/`\h`/`\t`/`\m`/`\[...\]`/`\x1b`，缺省 `cwd · model · [AI]:`——品红当前目录 + 暗色模型名 + 品红 `[AI]:` 文字标记；主屏方案下没有常驻状态行，这行是 rysh 显示当前模型的唯一位置，`/model` 切换后重绘即更新）；流式等待与工具执行都在内容**末行**就地显示 spinner（前后各留一空行；等模型 token 为 `⠋ 正在思考... 3s`，工具执行——含审批 y/a 之后到 `[tool]` 行落地——为 `⠋ 执行中... 3s`，含 grok 式连续计时：分钟以下 `Ns`，超过一分钟 `1m56s`；首个 token 或 `[tool]` 结果行到达即擦除让位）；忙碌期（从思考 spinner 到流式正文）终端光标隐藏、任务在新鲜提示符落地时恢复显示——spinner 与流式正文各自就是动态焦点，光标不必再标记焦点或输入位；提交后任务在流上原地流式输出（推理内容暗色、回复正常、工具执行行 `[tool] $ cmd (exit n)`），`^C` 终止（M7.3 起两级：工具执行阶段只中断当前前台命令、任务继续，流式阶段取消整个任务；M7.4 起待审批视同流式阶段——当前调用答拒绝并取消整个任务；M7.7 起三级——子任务运行中先停掉全部子任务、管理者续跑，再按才终止任务）；agent 循环（M7.2 起为 `internal/agent` 独立引擎）：原生 function calling 优先（模型不支持或 `tools = false` 时降级 markdown 围栏协议兜底），工具调用（bash/read/write/edit/glob/grep/ls/todo，M7.3 起 bash 超窗口自动转后台 job 并配 job_output/job_kill；M7.7 起管理者另有 task/task_output/task_kill——重活委派工人子智能体（独立上下文的 engine run，过程不进管理者上下文、只有紧凑状态与有界报告过缝），管理者轮询监控、判疯即停、验收总结；M7.4 起执行前过权限门——读类工具与命中安全分类器的 bash 直通，write/edit 与未命中 bash 弹琥珀色 `? 运行 …（y 是 / n 否 / a 总是）` 审批行（直接进滚动流；主屏方案下没有状态行可显示「等待确认」），`[agent] approval` 缺省 ask / 可设 auto，`a` 记会话级 bash 前缀或按工具规则，拒绝以文本回喂任务继续）执行后以 `role=tool` 结果回喂并再次调用模型，直到模型给出最终回答；引擎内置请求重试、死循环守卫 + 读空转守卫（先警告/提醒、后强制收尾总结）、自我警觉两级注入（§3.9⑧）与工具结果折叠（预算管理与循环防护见 §3.9，原「轮数上限 4」机制被其取代），同一任务内多轮共用一条 `─── <model> ───` 标题；斜杠命令 `/model` 切换模型（热重载配置）、`/new` 新建并切换会话、`/ls`/`/resume` 列出与切换会话（多会话见 §3.10）、`/history [页号]` 分页显示当前会话用户输入（`-v` 附模型回复；数据源即 messages.log 的 usr/asw 记录，与 ↑/↓ 召回同源）、未知命令报错。
- 后续增强：
  - 块状渲染 shell 命令块（需 shell 侧协同渲染，待定）。

### 3.9 Agent 预算管理、自动压缩与循环防护

> 取代原 `maxToolRounds = 4` 轮数上限。设计对标 2026-08 对头部 harness 的代码调研：OpenAI codex（无轮数上限 + auto-compact）、crush（StopWhen 双条件 + 签名循环检测）、zeroclaw（三级分级循环防护）、opencode（可选 steps + 强制收尾轮）、fx（窗口预算 + 静默步续跑）。核心结论：**轮数不是病，重复才是病**——正常长任务可含数百次不同工具调用，失控特征是「同命令+同输出」反复出现；能长时间运行靠的是压缩续命而非无限上下文。

**总原则**：agent 循环不设轮数硬上限。停止条件收敛为三种：用户 `^C`、LoopGuard 判定发疯、预算触顶。所有非常规退出汇入统一的强制收尾轮。

**① Token 记账（预算的前提）**
- 估算器逐消息计费：`CJK 字符 × 1.0 + 其余字符 ÷ 4`，加 10% 余量（中文场景比纯 `/4` 准）。
- `chatRequest` 增加 `stream_options: {"include_usage": true}`，`StreamToken` 携带末块 usage；每任务结束用真实 usage 校准估算系数。
- `Model.ContextWindow == 0`（未配置）时降级为字符总额预算（沿用 `session.MaxContext` 思路的放大版），功能不因缺配置失效。

**② BudgetManager 与压缩触发点**
- `有效窗口 = ContextWindow − 输出预留(MaxTokens 或默认 8K)`；soft 线 = 有效窗口 × 75%（触发压缩）；hard 线 = 有效窗口（转收尾轮）。
- **检查点只在轮界**：当前任务全部工具块执行完、下次调模型之前检查；绝不在工具批次中间打断（工具调用与结果必须成对，中途截断会产生悬空消息被协议拒收）。
- 膨胀主战场是 in-flight turn：现有 `trimHistory(40)` 只在任务结束后生效、`trimShellEvents` 只管 shell 事件，运行中的 turn 此前无任何约束。
- **2026-08-28 定案并实施**：压缩设计升级为"状态交接"（结构化 checkpoint + 存活状态快照重注入），触发线收敛为窗口 85%，75% 线让位给自我警觉提示；完整定案与实现说明见[agent执行流程设计 §10.3](./agent执行流程设计.md)（M7.6，`internal/agent/compact.go`）。

**③ 自动压缩（两级，从便宜到贵）**
- L1 工具输出瘦身（零模型成本）：滑动保留区之外的旧工具结果（请求视图内 role=tool 消息）替换为一行占位 `[已省略] $ <cmd> (exit n)，原始输出 N KB 已折叠；如需详情可重新运行该命令`。保留区按「从最新往旧累计 ≤64KB（`l1PreserveBytes`）」划定——恰好装满（合计=预算）不折叠；一旦溢出，其后更旧的整段折叠；无溢出则一条不动。占位符只进请求视图，`active.hist` 始终保留原文。
- L2 LLM 摘要压缩（**已按"状态交接"口径实施 2026-08-28**）：超触发线时把尾部保留线（≤25% 窗口）之前的整轮（保持「按整轮切、tool-pair-safe」不变式）交给**当前对话模型**做一次关 tools 的摘要调用，产出七段交接骨架（目标逐字/约束/进度/决策/下一步/关键上下文/备注）+ 机械段（文件清单 + 存活状态快照）合成 checkpoint；投影为 mission 逐字 + checkpoint + 切点后整轮，history 本体不动、磁盘仅追加 `compact` 事件。摘要期间屏幕 `─── compacting ───`，session log 记录。
- 不可压锚点（实施口径）：基础 system 三条（cwd/env/Instructions）、首条用户消息（mission）逐字、checkpoint、尾部保留 ≤25% 窗口的整轮原文。
- **出站 wire 形态（2026-08-31 实测定案）**：最严格的 OpenAI 兼容端点（sglang 等）要求 system 消息**恰好一条且位于 0 位**——开头连续多条 system、或首个非 system 之后出现 system，一律 400 "System message must be at the beginning"（宽松端点 DeepSeek/OpenAI 都接受）。内部上下文有意保持多 system：基础三条（cwd/env/Instructions）+ shell 事件与工具结果按时间线原位置各占一条，所以统一在 provider 出站口收敛（`provider.compliantSystem`，`ChatStream` 单一出口）：开头连续 system 合并为一条，其余 system 降格为带标记的 user 消息；引擎降级路径（无 tools 端点）的 role=tool 回喂同样用 user（`degradedTurn`），与 wire 规则一致。调用方切片永不被改写（内部视图保持会话自身角色，显示回放/裁剪/压缩过滤都依赖它）。
  > **进度注（2026-08-31 定案修订）**：中间 system 不再"降格为带标记的独立 user 消息"，改为**合并进下一条 user 消息内部**（标记行 + 上下文 + 用户原文，上下文在用户话语之上，"上述"指代落在同一条消息里）。三个 provider 出站形状一致：OpenAI 系经 `compliantSystem`（= `MergeContextIntoNextUser` + 开头 run 合并为 0 位一条 system，sglang 合规不变），Anthropic 与 Responses 在 `buildAnthropicMessages`/`buildResponsesInput` 之前同样先过 `MergeContextIntoNextUser`，开头 system run 进各自顶层字段（`system`/`instructions`），中间上下文不再丢失时间线位置。标记行只说明来源，不再写"非用户消息"之类的矛盾措辞。
- 迟滞防抖：压缩后回落到窗口 50% 以下才可能再次触发，避免每个来回反复触发。L2 失败降级为更激进 L1（失败撤防触发门，不在每轮界硬重试），永不因压缩本身杀死任务。
- history（跨任务）维持 `trimHistory` 整轮裁剪；M3 增强把被裁旧轮汇成 carry-over 摘要保留，减轻长会话跨任务失忆。

**④ LoopGuard 循环防护（分级，先劝后停）**
- 签名 = hash(`命令全文 + exit code + 输出前 N KB`)，三者绑定（单看命令会误伤合法的间隔查询如 tail 日志）。
- 滑动窗口默认 20 步记录签名，按连续相同签名计数升级：
  - **Warn ≥ 2**：回喂时附系统提示「相同命令相同输出已重复 N 次，状态未变化，请重新评估或汇报发现」（让模型自纠，成本为零）；
  - **Block ≥ 4**（M2，未实现）：不再执行该命令，直接返回错误文本 + 升级警告（强信号 + 省一次无意义执行）;
  - **Break ≥ 6** 或窗口内同签名占比 > 60%：终止任务转收尾轮。占比只在窗口**饱和（满 20 条）后**生效——样本不足时比率无意义（首条命令独占窗口即为 100%，会误杀新任务；单测 `TestLoopGuardFirstRecordIsNotLoops` 钉死该语义）。
- 静默步检测（M2）：连续 ≥ 2 轮仅工具调用且回复正文为空 → 注入 "Summarize what you just did." 式续跑提示（fx 机制）。
- 刻意不做「语义等价但参数微调」识别，启发式黑洞宁可漏报，兜底交给 `^C` 与可选成本预算。

**⑤ FinalRound 强制收尾（统一出口）**
- Block/Break、hard 触顶、（若配置）`max_turns` 到达，一律走同一出口：追加指令性消息「预算已到极限，不要再输出任何围栏块，立即基于已有信息输出：已完成工作 / 关键发现与修改 / 未完成部分与建议」；该轮检测到的围栏块直接丢弃不执行。
- 屏幕文案 `─── wrapping up (loop guard) ───`（暗色单行，原 exhausted 提示删除；后续预算类原因按 `(原因)` 追加）；穷尽不等于失忆。

**⑥ 配置面 `[agent]`（全可选，TOML，M3 落地）**：`keep_recent_turns=3`、`compact_trigger=0.75`、`compact_target=0.50`、`loop_window=20`、`loop_warn=2`（当前先按此值试用）、`loop_block=4`、`loop_break=6`、`max_turns=0`(不限)、`budget_usd=0`(不限)。

**⑦ 分期**：M1＝删轮数上限 + LoopGuard(Warn/Break) + FinalRound + 字符预算下的 L1 瘦身（**已实施 2026-08-27**：`cmd/rysh/loopguard.go` + main.go agent 循环改造；loopShareMinWindow 方案被「窗口饱和才计占比」取代；实现细节见 §3.9③④⑤ 更新与工作计划 2026-08-27 条目）；M2＝usage 接入校准（**已实施 2026-08-27，M7.2**：usage 上报优先、`reqChars/4` 估算兜底）+ 85%/50% 触发/回落的状态交接压缩（**已实施 2026-08-28，M7.6**：见 §3.9②③ 更新与[agent执行流程设计 §10.3](./agent执行流程设计.md) 已实现说明）+ 静默步检测（+Block 级，未实施）；M3＝配置面 TOML 化 + USD 成本统计 + carry-over 摘要。集成测试用现有 mock-server 手法覆盖：同签名循环的分级升级路径（已覆盖）、大输出的轮界压缩与摘要回灌（已覆盖，`TestAgentContextCompaction`）、未知窗口模型的长任务跑通。

**⑧ 自我警觉（M7.7，已实施 2026-08-28）**：agent 对自身状态保持警觉——上下文任何一部分异常变多、异常变大时主动检视。轮界两级一次性注入：请求体达窗口 50%（L1「上下文正在变重，省着用，优先委派子任务」）/ 75%（L2「接近上限，立即收尾」）；未配 `context_window` 时按估算 96k/144k token 兜底，另有消息数 ≥150 判据；度量取「当前请求 chars/4」与「上一轮 usage.PromptTokens」较大值（用当前请求评估，不滞后）。硬编码常量，配置化随 `[agent]` 面二期落地。

### 3.10 多会话（v6，已实施）

单进程单 pty 上持有多个 AI 会话：会话是磁盘流（`~/.rysh/sessions/<id>/messages.log`，append-only JSONL），不是进程也不是 pty——切换会话不创建第二份 pty，而是终止当前登录 shell 的**整棵进程树**（Windows 上 shell 是 `rysh.exe → bin\sh.exe 启动桩 → usr\bin\bash.exe 真身` 两代结构，只杀桩会留下孤儿真 shell 继续抢占同一个 ConPTY、把输入接走并冒充旧会话应答；故按 Toolhelp32/`/proc` 快照枚举后代、由深到浅终止，并等到它们真的消失）、把 pty 的 termios 复位为规范回显模式（被 SIGKILL 的行编辑器 shell 会把 pty 留在原始无回显态，不恢复则替换 shell 里用户输入不可见）、在同一个 pty 上重启登录 shell（重放 profile），屏幕上打一条分隔行 + 接该会话尾部回放（不清屏，主屏方案），草稿/AI 历史/事件环等每会话状态随之重置；磁盘历史永不覆盖。

- **台账**：`~/.rysh/created`（`<ts> <编号> <id>`，追加，编号自增）与 `~/.rysh/updated`（`<ts> <id>`，最近使用序）；无全局 current 指针，切换事实由「谁在附加 + 切换分隔行与通知」表达。
- **控制通道**：rysh 内执行 `rysh new`/`rysh resume` 是一次性子进程（`RYSH_INSIDE=1`），不嵌套 pty，而是向 `$RYSH_CTL`（`~/.rysh/ctl/<pid>.cmd`）写一行 `switch <id> <notice>`，当前实例主循环（250ms 轮询）读取后执行切换；`~/.rysh/ctl/<pid>.sess` 记录实例附加的会话，供互斥与 `rysh ls` 的 `[rysh <pid>]` 展示。
- **列表**：`/ls [页号]` 与 `rysh ls [页号]` 共用同一渲染（`renderSessionList`，每页 10 行，行首 `>` 标当前会话），六列为 编号 / ID / 名字 / 创建时间（created 台账）/ 最后更新（updated 台账的最近一条，无记录显示 `-`）/ 占用（`本实例`＝本次调用所属的 rysh 实例，`[rysh <pid>]`＝另一个存活实例正附加该会话，空＝无人占用）；时间列今年内为 `MM-DD HH:MM`、跨年为 `YYYY-MM-DD`；列宽按终端显示宽度对齐（CJK 字符占两列，用 `charmbracelet/x/ansi`.StringWidth）。
- **互斥与 kill**：一个会话同时只被一个实例附加；被附加会话拒绝切换（`/resume` 与 `rysh resume` 同文案并提示 `rysh kill`）；`rysh kill` 对附加者 SIGTERM → 5s → SIGKILL。
- **环境变量**：子 shell 与一次性子进程导出 `RYSH_INSIDE` / `RYSH_SESSION_ID` / `RYSH_CTL` / `RYSH_PID`。
- **入口**：AI 斜杠 `/ls` `/new` `/resume`；shell/任意终端 `rysh ls/new/resume/kill`；顶层形态 `rysh new` / `rysh resume <标识>`（直接进入指定会话）、`rysh ai`（AI 模式起步）；`rysh ai "<消息>"` 一次性问答。
- 流式任务进行中的切换请求挂起为 pendingSwitch，任务收尾后落地；切换落地杀登录 shell 可能抢在子命令子进程回显退出码之前，确认信息以实例播报的通知为准。

## 4. 数据流

```
键盘 → pty master → 输入路由
   ├─ Shell 模式 → pty master → 登录 shell → 输出透传 → 屏幕（同一屏幕/同一流）
   └─ AI 模式 → 同一屏幕：AI 提示行原地替换 shell 提示行
        ├─ Shift+Tab 进入 → shell 未提交命令带进 AI 草稿（shell 侧清空该行：行编辑器 shell ^A+^K、纯 shell ^U），光标列随草稿带入
        ├─ 草稿提交 → 斜杠命令（本地处理） / agent loop → 流式回复注入同一流
        └─ Shift+Tab 退出 → AI 草稿原样回注入 shell（不带回车），按列差补发左方向键回注光标列（仅行编辑器 shell），shell 自行重绘提示行
       （shell 与 AI 共用同一条输入行：任一侧提交或清空都会消耗这一行；
          AI 模式下 pty 输出暂不转发：记录到会话日志，返回时一次性刷新到屏幕）
会话日志（append-only JSONL）⇄ AI 会话（cwd 随事件携带）
cwd/环境 跟踪：登录 shell → 状态同步 → rysh 上下文
```

## 5. 关键设计决策（ADR 摘要）

1. **shell 与 AI 共用一条输入行**：Shift+Tab（或行首空格）切换 shell⇄AI；进入 AI 时 shell 未提交的命令带进 AI 草稿、shell 侧清空该行（带行编辑器的 shell 以 ^A+^K、纯 shell 以 ^U）；退出时 AI 草稿回注入 shell 命令行（不带回车）；任一侧提交或清空都会消耗这一行，文本与光标位置随切换延续（shell 光标所在列带进 AI 草稿，切回时按列差补发左方向键把 shell 光标回注到同一列，仅对带行编辑器的 shell）。多轮会话常驻 AI 编辑器，跨模式切换存活；Esc 只清空草稿。AI 编辑器提供 ↑/↓（Ctrl-P/Ctrl-N）用户输入轮换：列表取当前会话日志的 `usr` 记录（进 AI 模式与切换会话时重读，每次提交追加），自最近一条起逐条选中回填草稿，继续编辑即脱离轮换、越过最近一条恢复当前草稿。任务流式期间锁定切换，仅 `^C` 终止。草稿以 `!` 开头视为误输入到 AI 模式的 shell 命令：不执行、不发给模型，提交时保留草稿并提示两条出路（模式切换键切换并保留输入、切换时去掉行首 `!` 回注；或清空草稿后行首空格切换再输入）。
2. **cwd-as-data 而非进程粘性状态**：会话不绑目录，cwd 是事件字段，天然支持目录切换与上下文出处。
3. **Go 而非 Rust/Zig**：静态单文件分发内置（`CGO_ENABLED=0`）+ 终端/PTY/并发生态成熟；团队更熟 Go，迭代快。生态查证见[技术选型调研](./技术选型调研.md)。
4. **不做多任务**：交给 tmux，聚焦交互体验。
5. **不绑定本地模型**：provider 抽象，本地/云端自由；不考虑自进化。
6. **三平台支持，Windows 默认 PowerShell**：Linux/macOS 包装登录 shell（`$SHELL -l`）；Windows 无登录 shell，按 `pwsh` → `powershell` → `cmd` 探测默认 shell 并加载其 profile，`shell = "auto"` 可在 `~/.rysh/config.toml` 覆盖。PTY 层跨平台统一走 `aymanbagabas/go-pty`（Unix=creack/pty，Windows=ConPTY）。
7. **一屏一流**（v4，修订 Route C 的 alt-screen 全量视图；主屏方案再修订）：AI 与 shell 共享同一屏幕、同一条终端流，会话连续，且全程留在终端主屏。进入/退出 AI 模式不切 alt screen、不清屏、不动滚动区、不改终端光标、不回放/重建 shell 画面；AI 模式下 shell 输出缓冲 + 记录日志，返回时一次性刷新，裸 `\r` 让 shell 自绘提示行完成重同步。任务流式期间锁定模式切换（切换键被忽略并打一条暗色通知，仅 `^C` 终止）。取舍：AI 视图不再是会话级独立屏（无独立滚动区、块状渲染），也不再有任何钉住的指示器（状态栏与光标联动一并取消，`[tui] cursor_style` 失效），换来的是 shell 与 AI 输出都进入终端原生 scrollback、`Shift+PgUp` / 滚轮可直接回看；代价是长回复把 `[AI]:` 提示符滚进历史时没有常驻模式指示。shell 侧字节级透传与 vim/less 全屏程序完全不受影响。
8. **无轮数上限的 agent 循环**（§3.9）：移除 `maxToolRounds` 计数器。调研证实头部 harness 无一家依赖小轮数上限：codex/grok-build/crush/pi/zeroclaw/fx 的主循环均无界，靠「重复签名分级防护」防发疯、靠「token 预算驱动自动压缩」续命。计数误伤正常的多步调查任务；循环检测绑定「命令+退出码+输出」三元组签名以放过合法的间隔查询。一切非常规终止汇入 FinalRound 强制收尾，模型永远有机会汇报进展而非戛然而止。
9. **AI 模式 = 管理者模型**（M7.7，[agent执行流程设计 §16](./agent执行流程设计.md)）：传统 shell 本体永远是管理者和监控者——准备参数/env/cwd、等待、收尸工具进程；AI 模式的核心是上下文管理，管理者像守财奴一样吝啬，竭尽全力减少对自身上下文的污染。除极简/关乎自身的任务外，重活一律委派工人子智能体（同进程、独立上下文的 engine run，复用全套守卫），过程不进管理者上下文、只有紧凑状态与有界报告过缝；管理者派遣、轮询监控、判疯即停（主动 kill + 守卫强制收尾双保险）、干完后验收与总结，自身上下文只留使命、todo 与子任务状态。任务在自身子任务运行中不能结束：引擎先提醒一次（引擎不会在子任务完成时重新唤醒模型），仍要结束则引擎自己等待子任务全部结束、把最终状态与报告回喂，模型验收后收尾；守卫强制收尾轮同理（先收报告再收尾）。^C 三级语义（审批→拒答、命令→只中断命令、子任务→先停子任务管理者续跑）。不做子任务嵌套（深度 1）、不做子任务独立模型/独立审批。

## 6. 非目标 / 明确不做

- 多任务/多窗口管理（tmux 负责）。
- 模型自进化。
- 与 wukong 的代码合并或共享底座（方向与技术栈不同，独立演进）。
